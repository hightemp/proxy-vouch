# ProxyVouch — требования к продукту

Версия документа: 1.1. Дата: 2026-09-06. Статус: реализация в работе; подготовлена первая рабочая Linux-версия, полная приёмка MVP ещё не завершена. Фактические возможности и запуск описаны в [README.md](README.md).

Связанный план: [TASKS.md](TASKS.md).

## 1. Назначение и язык

**ProxyVouch** — удобное десктопное приложение на Tauri для массовой проверки прокси. Пользователь вставляет список в разных форматах или открывает файл, запускает проверку, получает понятные результаты и копирует либо сохраняет нужную часть списка.

PRD.md и TASKS.md ведутся на русском. Интерфейс, исходный код, имена сущностей, комментарии, сообщения ошибок, README и остальная документация проекта — на английском. Примеры элементов интерфейса в этом документе также приведены на английском.

Основной сценарий должен работать без регистрации, облачного аккаунта, настройки системного прокси и прав администратора. Данные обрабатываются локально; для сетевой проверки приложение обращается к указанным прокси и тестовым адресам.

## 2. Цели и границы первой версии

### 2.1. Цели

- Принимать смешанные списки без ручного приведения каждой строки к одному формату.
- Автоматически определять протокол, если он не указан.
- Подтверждать работоспособность реальным запросом через прокси.
- Показывать причину неудачи и отличать её от ошибки импорта или неопределённого результата.
- Позволять быстро получить рабочие, нерабочие, все проверенные или выбранные записи в буфере обмена и файле.
- Сохранять отзывчивость интерфейса при больших списках и параллельных проверках.

### 2.2. Состав MVP

Импорт из текста, буфера обмена и файлов TXT/CSV/TSV; предпросмотр и исправление строк; HTTP, HTTPS, SOCKS4, SOCKS4a, SOCKS5; автоматическое определение; проверка авторизации и запроса к тестовому адресу; внешний IP для профиля IP echo; время запроса; фильтрация и сортировка; запуск, отмена и повторная проверка; экспорт TXT/CSV/JSON; настройки проверки; автоматическое сохранение рабочей сессии и переносимые резервные копии.

Целевые системы: Linux, Windows и macOS. Первая среда разработки и приёмки — Linux. Готовность Windows и macOS подтверждается отдельно нативными сборками и проверкой GUI; успешная Linux-сборка не подтверждает готовность других платформ. Минимальные версии ОС и архитектуры фиксируются после технического исследования T-001.

### 2.3. За пределами MVP

- VPN/TUN, переключение системного прокси, проксирование других приложений и цепочки прокси.
- Поиск прокси в интернете, подписки по URL, сканирование диапазонов адресов и портов.
- UDP ASSOCIATE, QUIC, HTTP/3, HTTP/2-only proxy, PAC/WPAD, SSH-туннели, Shadowsocks, VLESS, VMess и Trojan.
- SOCKS5 GSSAPI, HTTP Digest/NTLM/Kerberos и клиентские TLS-сертификаты.
- Определение анонимности, репутации, residential/datacenter, геолокации и доступности отдельных коммерческих сервисов.
- Измерение пропускной способности, фоновые расписания, история всех запусков сверх последнего результата, синхронизация и автообновление.

## 4. Импорт и разбор записей

### FR-01. Источники и предпросмотр

- Многострочное поле `Paste proxies`, кнопка `Paste from clipboard`, системный диалог `Import file` и drag-and-drop файлов.
- TXT: одна запись на строку, форматы строк могут отличаться. CSV/TSV: одна запись на строку таблицы, единая схема колонок на файл.
- Кодировка UTF-8, с BOM или без него; переводы строк LF и CRLF. Ошибка кодировки показывается явно, байты не заменяются молча.
- До добавления показываются `Valid`, `Invalid`, `Duplicates`, `Ignored`, исходный номер строки и замаскированные разобранные поля.
- Ошибка одной строки не блокирует остальные. Доступны редактирование и `Import valid`; отклонённые строки остаются доступными для исправления или сохранения.
- Действия над существующим списком: `Append` по умолчанию, `Replace` явно. При активной проверке импорт, редактирование, удаление и замена списка недоступны до её остановки.
- Лимиты MVP: 100 000 записей в списке, 20 MiB на файл или вставку, 8 KiB на строку/CSV-запись. Превышение объясняется до частичного добавления.

### FR-02. Поддерживаемые форматы

Все адреса и реквизиты ниже синтетические. Пример исходного пользовательского формата представлен с заменёнными значениями.

| ID | Формат | Пример | Обработка |
| --- | --- | --- | --- |
| F-01 | `host:port` | `192.0.2.10:8080` | Протокол `Auto` |
| F-02 | `host:port:username:password` | `192.0.2.10:64239:demo-user:demo-pass` | Протокол `Auto` |
| F-03 | `username:password@host:port` | `demo-user:demo-pass@proxy.example:1080` | Протокол `Auto` |
| F-04 | `scheme://host:port` | `http://proxy.example:8080` | Явный протокол |
| F-05 | `scheme://username:password@host:port` | `socks5://demo-user:demo-pass@proxy.example:1080` | Явный протокол и реквизиты |
| F-06 | `host:port protocol` | `192.0.2.10:1080 socks5` | Протокол в конце |
| F-07 | `host:port:username:password protocol` | `192.0.2.10:64239:demo-user:demo-pass socks5` | Формат исходного примера |
| F-08 | `protocol host:port` | `https proxy.example:8443` | Протокол в начале |
| F-09 | `protocol host:port:username:password` | `socks5 proxy.example:1080:demo-user:demo-pass` | Протокол в начале |
| F-10 | `username:password@host:port protocol` | `demo-user:demo-pass@proxy.example:1080 socks5` | Реквизиты перед адресом |
| F-11 | `[ipv6]:port` | `[2001:db8::10]:1080` | IPv6 в скобках, `Auto` |
| F-12 | URI с IPv6 и авторизацией | `socks5h://demo-user:demo-pass@[2001:db8::10]:1080` | IPv6 в URI |
| F-13 | IPv6 и реквизиты после порта | `[2001:db8::10]:1080:demo-user:demo-pass socks5` | Скобки защищают двоеточия адреса |
| F-14 | URI HTTPS-прокси | `https://demo-user:demo-pass@proxy.example:8443` | TLS-соединение с прокси |
| F-15 | URI SOCKS4 / SOCKS4a | `socks4://192.0.2.10:1080`, `socks4a://proxy.example:1080` | Соответствующий режим SOCKS4 |
| F-16 | SOCKS4 с USERID | `socks4a://demo-user@proxy.example:1080` | USERID, без пароля |
| F-17 | URI с экранированными реквизитами | `http://demo%40user:p%3Aa%25ss@proxy.example:8080` | Логин `demo@user`, пароль `p:a%ss` |
| F-18 | Колонки через пробелы | `proxy.example 1080 demo-user demo-pass socks5` | Автоматически только порядок `host port [username password] [protocol]` |
| F-19 | CSV, `,` или `;` | `proxy.example,1080,demo-user,demo-pass,socks5` | Предпросмотр колонок; CSV-кавычки |
| F-20 | TSV | `host<TAB>port<TAB>username<TAB>password<TAB>protocol` | `<TAB>` обозначает настоящий символ табуляции |
| F-21 | Обратный порядок через двоеточия | `demo-user:demo-pass:proxy.example:1080` | Только явно выбранный шаблон `username:password:host:port` |
| F-22 | Нестандартные колонки | `socks5;proxy.example;1080;demo-user;demo-pass` | С заголовком либо ручным сопоставлением колонок |

F-21 не распознаётся угадыванием: числовой пароль и похожий на адрес логин могут дать два корректных разбора. Произвольные перестановки токенов вне таблицы не обещаются; приложение предлагает формат с URI либо сопоставление колонок.

### FR-03. Правила синтаксиса и нормализации

1. Названия схем и протоколов нечувствительны к регистру: `http`, `https`, `socks4`, `socks4a`, `socks5`, `socks5h`. `auto` разрешён как значение колонки или отдельный токен; URI `auto://` не используется. Неоднозначное `socks` требует уточнения.
2. Явная схема и отдельный токен протокола могут сочетаться только при полном согласии, включая режим DNS. Конфликт вроде `http://proxy.example:8080 socks5` — `PROTOCOL_CONFLICT`.
3. Отсутствие протокола означает `Auto`, а не HTTP. Номер порта не задаёт протокол. Порт обязателен, целое число от 1 до 65535; значения по умолчанию не подставляются.
4. Host: IPv4, DNS-имя, `localhost` или IPv6. IPv6 в записи с портом обязателен в `[]`. Link-local zone ID в MVP не поддерживается. DNS-имена нормализуются в нижний регистр и IDNA ASCII; регистр и содержимое реквизитов сохраняются.
5. URI разбирается URI-парсером. В userinfo зарезервированные символы кодируются через percent-encoding и декодируются ровно один раз. `+` остаётся плюсом. Некорректный `%XX`, NUL, CR/LF и управляющие символы в полях отклоняются.
6. В URI допустим пустой путь или завершающий `/`; непустой путь, query и fragment у адреса прокси отклоняются. Они не являются метками или настройками прокси.
7. В компактных форматах F-02/F-03/F-07/F-09/F-10/F-13 реквизиты не содержат необработанные `:`, `@` и пробельные разделители. Для таких реквизитов используются F-17 или CSV/TSV с явными колонками. Вне URI percent-encoding не декодируется.
8. Пустые строки и TXT-строки, начинающиеся после пробелов с `#` или `//`, игнорируются. Комментарии в конце записи не поддерживаются: `#` внутри пароля не отрезается.
9. В TXT удаляются только внешние пробелы записи. F-18 имеет 2, 3, 4 или 5 полей; третье поле в трёхполной форме — протокол. Неполная пара логин/пароль не достраивается.
10. В CSV/TSV заголовки сопоставляются без учёта регистра: `host/ip/server`, `port`, `username/user/login`, `password/pass`, `protocol/type/scheme`. Допускается одна колонка `proxy` с полной записью и необязательный `label`. Несопоставленные колонки можно явно игнорировать в предпросмотре.
11. Без заголовка предлагается схема `host,port,username,password,protocol`; для двух колонок — `host,port`. Другая схема требует выбора. Разделитель и заголовок можно переопределить; некорректные кавычки показываются как ошибка. Переводы строк внутри поля отклоняются.
12. Отсутствие реквизитов отличается от пустого пароля. HTTP(S) допускает непустой логин с явно пустым паролем. SOCKS5 username/password требует по 1–255 байт на каждое поле; используется UTF-8 без изменения исходных символов. SOCKS4 поддерживает необязательный USERID; пароль не игнорируется, а вызывает `UNSUPPORTED_AUTH`. Основание для ограничений SOCKS5: [RFC 1929](https://datatracker.ietf.org/doc/html/rfc1929).
13. `scheme://host:port:username:password`, pipe-форматы, JSON-конфиги сторонних клиентов и строки с неизвестными схемами не разбираются по догадке; показывается подсказка с поддерживаемым шаблоном.

### FR-04. Дубликаты и редактирование

Ключ дубликата: нормализованные host и port, заданный протокол, режим DNS, точные username/password и различие между отсутствующим и пустым значением. `Auto` и явно заданный протокол считаются разными записями. Разные пароли, SOCKS5 local DNS и remote DNS не объединяются.

По умолчанию дубликаты пропускаются с отдельным счётчиком; опция `Keep duplicates` оставляет независимые строки. Сверка работает и внутри импорта, и с текущим списком. Исходные строки и номера сохраняются в памяти. После проверки автоматическое объединение записей не выполняется.

Редактирование адреса, реквизитов или протокола сбрасывает результат строки в `Unchecked`. Последний результат хранит снимок профиля проверки; при изменении профиля он не переименовывается задним числом и отмечается как результат другого профиля.

## 5. Протоколы и автоматическое определение

### FR-05. Матрица протоколов

| Режим | Соединение с прокси | Доступ к целевому адресу | Авторизация MVP | DNS целевого имени |
| --- | --- | --- | --- | --- |
| HTTP | TCP | HTTP forward для HTTP; CONNECT для HTTPS | Без авторизации, Basic | Имя передаётся прокси |
| HTTPS | TLS к прокси, HTTP/1.1 внутри TLS | HTTP forward либо CONNECT | Без авторизации, Basic | Имя передаётся прокси |
| SOCKS4 | TCP | SOCKS CONNECT к IPv4-назначению | Необязательный USERID | Локальный |
| SOCKS4a | TCP | SOCKS CONNECT с именем назначения | Необязательный USERID | На прокси |
| SOCKS5 | TCP | SOCKS CONNECT; IPv4/IPv6/имя | Без авторизации, username/password | `socks5`: локальный; `socks5h`: на прокси |

`https://` описывает TLS до самого прокси. Обычный `http://` также может открывать HTTPS-сайты через CONNECT. `socks5h` — SOCKS5 с другим режимом разрешения имени, а не отдельная версия протокола. Эти различия согласованы с [документацией curl о схемах прокси](https://curl.se/libcurl/c/CURLOPT_PROXY.html) и [семантикой HTTP CONNECT](https://www.rfc-editor.org/rfc/rfc9110.html#name-connect).

Для SOCKS4/4a не обещается IPv6-назначение; доступность самого IPv6-адреса прокси зависит от транспорта и проверяется отдельно. Возможности SOCKS5 опираются на [RFC 1928](https://datatracker.ietf.org/doc/html/rfc1928); MVP использует только CONNECT и перечисленные методы авторизации.

### FR-06. Автоматическое определение

1. При явном протоколе проверяется только он и заданный режим DNS. В строке показываются `Requested protocol` и, если доказан ответом, `Detected protocol`. Ошибочно указанный протокол не заменяется молча.
2. Для `Auto` используются последовательные кандидаты на отдельных соединениях: HTTPS → SOCKS5 с remote DNS → HTTP → SOCKS4a → SOCKS4. Это детерминированный порядок, а не определение по номеру порта.
3. Кандидаты, несовместимые с реквизитами или семейством целевого адреса, пропускаются с объяснением. В частности, при наличии пароля не выполняется SOCKS4/4a с отбрасыванием пароля.
4. Для каждого кандидата выполняются протокольное согласование, допустимая авторизация и контрольный запрос. Первый полностью успешный кандидат завершает проверку. Остальные кандидаты не перебираются; результат не утверждает, что сервер поддерживает только найденный протокол.
5. Корректный SOCKS-ответ или ответ HTTP-прокси может подтвердить протокол даже при отказе авторизации/CONNECT. Открытый TCP-порт, случайный HTTP 200 и успешный TLS handshake сами по себе работоспособность прокси не подтверждают.
6. Неуспех кандидата позволяет перейти к следующему в рамках общего срока проверки. Сохраняется краткая диагностика каждого кандидата. Истечение общего срока до окончания перебора означает `Inconclusive` с `DETECTION_INCOMPLETE`.
7. При неопознанных ответах всех кандидатов — `Inconclusive / PROTOCOL_NOT_DETECTED`. При однозначном сетевом отказе или подтверждённой ошибке прокси применяется классификация FR-08. Ошибки аутентификации и TLS не скрываются последним таймаутом другого кандидата.
8. В `Auto` поддерживается только remote DNS для SOCKS5. Успешный результат экспортируется как `socks5h://`. Проверить SOCKS5 с local DNS можно явным выбором `socks5`; автоматического изменения DNS после ошибки нет.
9. Для явно заданного HTTPS ошибки сертификата не включают переход к plaintext HTTP. В `Auto` HTTP является самостоятельным кандидатом; интерфейс показывает фактически использованный транспорт.
10. При повторной проверке `Auto` найденный ранее режим может идти первым; результат всё равно подтверждается новым запросом. Если он не работает, выполняется оставшийся перебор. Изменение записи очищает эту подсказку.

Пользователь может явно выбрать `Detect again` для записей с ошибочно указанной схемой: это меняет выбранные записи на `Auto` и запускает новую проверку.

## 6. Проверка и интерпретация результата

### FR-07. Контрольный запрос

Профиль по умолчанию — `HTTPS IP check`: GET `https://api64.ipify.org?format=json`, HTTP 200, корректный JSON с полем `ip`, содержащим IPv4 или IPv6. Адрес и формат ответа опубликованы в [документации ipify](https://www.ipify.org/). Это внешний сервис, его доступность не гарантируется приложением.

Пользователь может создать профиль `Custom URL`: HTTP/HTTPS URL, ожидаемые коды ответа и необязательная строка в теле. В custom-профиле внешний IP остаётся пустым, если профиль не имеет явно выбранного валидатора IP echo. Поддерживаются основной и необязательный резервный адрес; правила проверки ответа для каждого заданы отдельно.

Порядок проверки: разрешение адреса прокси → TCP → при необходимости TLS к прокси → протокол/авторизация → соединение с назначением → для HTTPS назначения TLS внутри туннеля → GET → проверка статуса и тела.

- Все контрольные запросы, включая резервный, проходят через проверяемый прокси. Системные HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY и настройки ОС не меняют выбранный маршрут; прямого fallback нет.
- Имя самого прокси при необходимости разрешается локально. DNS целевого имени следует режиму FR-05 и отражается в результате.
- Для обоих TLS-слоёв проверяются цепочка доверия и имя/IP сертификата. При IP-адресе не подставляется выдуманный SNI. Отключение проверки сертификатов в MVP отсутствует.
- Redirect по умолчанию не выполняется; 3xx — неожиданный ответ. В MVP профиль задаёт конечный URL, переходы с реквизитами не реализуются.
- Нет cookies, пользовательской сессии, выполнения JavaScript и загрузки ресурсов страницы. Лимит заголовков 32 KiB, декодированного тела 64 KiB; превышение завершает запрос контролируемой ошибкой.
- `Latency` — время успешной попытки от начала разрешения адреса прокси до получения и валидации ответа. Ожидание очереди и предыдущие кандидаты не входят. `Total duration` включает все кандидаты текущей проверки после выхода из очереди. Это не ICMP ping и не скорость канала.
- `Working` означает успех для конкретного профиля в указанное время. Он не обещает анонимность, доступность всех сайтов или будущую стабильность. Различие внешнего IP и локального IP не является условием успеха.
- Отдельное поле `Authentication` имеет значения `Not required`, `Authenticated`, `Not tested`, `Failed`. Если сервер пропустил запрос без использования переданных реквизитов, результат может быть `Working / Not required`; правильность пароля в таком случае не подтверждена. SOCKS4 USERID отражается как переданный идентификатор, без заявления о проверке пароля.
- Для HTTP-профиля `Working` не подтверждает поддержку HTTPS CONNECT; профиль и проверенная возможность видны рядом с результатом и в отчёте.

### FR-08. Состояния и причины

| Статус UI | Значение | Участие в быстрых экспортных группах |
| --- | --- | --- |
| `Unchecked` | Корректная запись ещё не проверялась | Только `All` / `Selected` |
| `Queued` | Ожидает свободного слота | Только `All` / `Selected` |
| `Checking` | Выполняется проверка | Только `All` / `Selected` |
| `Working` | Контрольный запрос прошёл все условия | `Working`, `Checked` |
| `Failed` | Проверка завершилась конкретной ошибкой соединения/прокси | `Failed`, `Checked` |
| `Inconclusive` | Данных недостаточно для оценки | `Inconclusive`, `Checked` |
| `Cancelled` | Проверка не завершена по действию пользователя | Только `All` / `Selected` |
| `Invalid` | Ошибка входных данных | Только отчёт / исходные строки |

`Checked` = `Working` + `Failed` + `Inconclusive` текущих отображаемых результатов. Приложение не объединяет `Invalid`, `Cancelled` и `Inconclusive` с нерабочими прокси.

| Группа | Примеры кодов | Правило результата |
| --- | --- | --- |
| Входные данные | `INVALID_FORMAT`, `INVALID_HOST`, `INVALID_PORT`, `PROTOCOL_CONFLICT`, `UNSUPPORTED_PROTOCOL`, `UNSUPPORTED_AUTH` | `Invalid` до сети; несовместимый отдельный Auto-кандидат только пропускается |
| Адрес/транспорт | `PROXY_DNS_FAILED`, `CONNECTION_REFUSED`, `CONNECT_TIMEOUT`, `CONNECTION_RESET` | `Failed`, если нет признаков общей локальной ошибки; причина и стадия обязательны |
| Авторизация | `AUTH_REQUIRED`, `AUTH_FAILED` | `Failed`; при успешном согласовании протокол сохраняется |
| Возможность клиента | `AUTH_METHOD_UNSUPPORTED`, `ADDRESS_TYPE_UNSUPPORTED` | `Inconclusive`; сервер не объявляется нерабочим из-за ограничения клиента |
| TLS к прокси | `PROXY_TLS_INVALID` | `Failed` для выбранного TLS-режима; подтверждение HTTPS-прокси не выдумывается |
| Прокси/туннель | `CONNECT_DENIED`, `SOCKS_REQUEST_REJECTED` | `Failed` для выбранного назначения; отдельно код ответа прокси |
| Проверочный адрес | `TARGET_HTTP_ERROR`, `TARGET_TLS_INVALID`, `UNEXPECTED_RESPONSE`, `RESPONSE_TOO_LARGE`, `TARGET_TIMEOUT` | Резервный адрес, если задан; без успеха — `Inconclusive` |
| Среда/определение | `LOCAL_NETWORK_ERROR`, `LOCAL_DNS_FAILED`, `PROTOCOL_NOT_DETECTED`, `DETECTION_INCOMPLETE`, `INTERNAL_ERROR` | `Inconclusive`, диагностируемая причина |

HTTP 407 относится к авторизации прокси; HTTP 401/403/429/5xx целевого сервиса — к ответу назначения. HTTP 403 на CONNECT отличается от HTTP 403 внутри успешно установленного туннеля. При нескольких неудачах Auto сохраняется наиболее предметная подтверждённая причина и все попытки, а не только последняя ошибка.

Если контрольный адрес массово отвечает 429/5xx, запуск новых запросов к нему приостанавливается с сообщением `Check endpoint unavailable`; пользователь может остановить запуск или сменить профиль и начать заново. Порог: не менее 5 таких ответов и не менее 80% среди последних до 20 ответов этого адреса в запуске. Уже завершённые результаты не переписываются; незавершённые проверки без успешного резервного адреса получают `Inconclusive`.

Нет скрытых прямых интернет-запросов для «подтверждения», что не работает сам прокси. Неопределённая причина остаётся неопределённой; сетевой таймаут означает неуспех данной попытки, а не постоянную недоступность узла.

### FR-09. Планировщик, лимиты и повтор

| Параметр | По умолчанию | Допустимый диапазон |
| --- | --- | --- |
| Одновременно проверяемых записей | 20 | 1–200 |
| Запуск новых сетевых попыток | 10/с глобально | 1–100/с |
| Разрешение адреса прокси + TCP | 3 с | 1–30 с |
| Одна попытка кандидата целиком | 8 с | 2–60 с |
| Вся проверка одной записи | 45 с | 5–300 с |
| Дополнительные повторы временной ошибки | 0 | 0–2 |

Сроки вложены: TCP/DNS ≤ попытка ≤ запись. Общий срок начинается при получении слота записи; ожидание ограничения частоты, все кандидаты, резервные адреса, повторы и задержки входят в него. Уменьшение бюджета может дать `DETECTION_INCOMPLETE`; интерфейс показывает это до запуска. Резервный запрос — новая попытка в оставшемся бюджете.

Одновременно на запись выполняется одна сетевая попытка. Rate limit применяется также к новым кандидатам, резервным запросам и повторам. Настройки выше описывают пределы клиента и не обещают допустимую нагрузку конкретного публичного сервиса.

Повторяются только временные сетевые ошибки, с задержками 500 мс и 1 с и небольшим jitter. Ошибки формата, авторизации, сертификата и неподдерживаемого метода не повторяются автоматически. `Retry failed`, `Retry inconclusive`, `Check selected` и `Check all` доступны явно.

Настройки фиксируются на запуск; изменения применяются к следующему запуску. Допускается один запуск одновременно. `Stop` отменяет очередь и текущие операции, сохраняет законченные результаты. Повторный `Start` обрабатывает явно выбранную группу. События завершённого или отменённого запуска не могут изменить результат нового запуска.

## 7. Интерфейс и работа с результатами

### FR-10. Основное окно

- Верхняя панель: `Paste proxies`, `Import file`, `Check all`, `Check selected`, `Stop`, `Settings`.
- Счётчики: всего записей, очередь, проверяются, `Working`, `Failed`, `Inconclusive`, отменённые; прогресс `completed / scheduled`. Невалидные записи отдельно от прогресса сетевой проверки.
- Фильтры: `All`, `Working`, `Failed`, `Inconclusive`, `Unchecked`, `Invalid`, `Cancelled`; поиск по host, username и label, без поиска по паролю.
- Таблица: выбор, `Proxy`, `Protocol`, `Status`, `Latency`, `Exit IP`, `Checked at`, `Error`. Сортировка по адресу, статусу, протоколу, времени и задержке; пустые значения задержки всегда после измеренных.
- Строка деталей: исходный формат с маской, requested/detected protocol, режим DNS, наличие авторизации, профиль/адрес проверки, длительность, стадии и ошибки попыток.
- Панель экспорта: быстрые `Copy working`, `Save working`, `Copy failed`, `Save failed`; меню для остальных групп и форматов. После действия показывается точное количество записей.
- Контекстное меню: `Check`, `Edit`, `Copy`, `Remove`, `Detect again`. Есть множественное выделение, `Ctrl/Cmd+A`, клавиатурная навигация, доступные подписи, состояния без зависимости только от цвета.
- Светлая и тёмная темы, системная тема по умолчанию. Минимальный размер окна 1000×650; таблица виртуализирована, длинные значения доступны в деталях.

Закрытие окна во время проверки предлагает `Stop, save and quit` / `Keep checking`. В обычном состоянии окно закрывается после сохранения без дополнительного диалога. Индикатор показывает `Saved locally`, `Saving…` или `Not saved`; ошибка записи остаётся видимой. Если сохранение при закрытии не удалось, окно остаётся открытым: доступны повтор сохранения, продолжение работы и явный выход без сохранения новых изменений.

## 8. Копирование и сохранение

### FR-11. Экспорт

Одинаковый механизм формирует данные для буфера обмена и файла. Независимо выбираются область, формат и наличие реквизитов.

| Параметр | Варианты |
| --- | --- |
| Область | `Working`, `Failed`, `Checked`, `Inconclusive`, `Selected`, `Filtered`, `All` |
| Формат | TXT `Proxy URLs`, TXT `Original lines`, TXT `host:port:user:pass protocol`, CSV `Report`, JSON `Report` |
| Реквизиты | `Include credentials` включено для пригодного к повторному использованию списка; выключено по умолчанию для отчёта |

- `Working` и `Failed` охватывают соответствующие строки всего списка; активный фильтр их не сужает. `Filtered` экспортирует видимые по фильтру строки, `Selected` — выделенные. Предпросмотр показывает область и количество.
- URI использует успешно проверенный протокол; если успеха нет — заданный пользователем. Для `Auto` без успешного результата URI недоступен, даже если протокол частично распознан. Предлагаются `Original lines` или отчёт; схема не подставляется по догадке.
- `Copy working` по умолчанию копирует URI с реквизитами. `Copy failed` по умолчанию копирует исходные строки с реквизитами, чтобы сохранить исходные параметры повторной проверки. Аналогичные правила у `Save working`/`Save failed`.
- В TXT URI/компактном формате строки разделяются LF. IPv6 сохраняет скобки; реквизиты в URI корректно кодируются; SOCKS5 remote DNS остаётся `socks5h`.
- Компактный формат недоступен для строк, где реквизиты содержат неоднозначные разделители либо протокол не выбран/не подтверждён. Пользователю предлагается URI или исходный формат. Непредставимые строки не пропускаются молча.
- `Original lines` сохраняет исходные записи, включая их формат; для CSV/TSV сохраняет необходимые заголовки и выбранный разделитель. Если выборка смешивает табличные схемы или текст с таблицами, предлагается отчёт либо нормализованный список, без склейки неоднозначного файла.
- `Include credentials = off` удаляет реквизиты структурно и не записывает `***` как пароль. `Original lines` доступен только с включёнными реквизитами, если они были в источнике; для обезличивания предлагается отчёт. UI явно показывает, включены ли пароли.
- CSV/JSON отчёт содержит `id`, `source_name`, `source_line`, `host`, `port`, `requested_protocol`, `detected_protocol`, `dns_mode`, `authentication`, `status`, `error_code`, `error_stage`, `error_message`, `latency_ms`, `total_duration_ms`, `exit_ip`, `checked_at`, `profile`, `check_url`; реквизиты только при включённой опции. JSON содержит `schema_version` и структурированные попытки. CSV имеет одну строку на прокси, UTF-8 и экранирование полей.
- CSV-отчёт защищает текстовые ячейки от интерпретации как формулы (`=`, `+`, `-`, `@` и управляющие префиксы). Он предназначен для просмотра; для точного машинного переноса служат URI/JSON. Такое преобразование явно описано в экспорте.
- Сохранение через системный диалог; корректная обработка отмены, перезаписи, отказа в доступе, нехватки места и ошибок буфера обмена. Запись файла атомарная через временный файл в том же каталоге, где поддерживается; ошибка не уничтожает существующий файл.
- Во время проверки экспортируется снимок строк на момент нажатия; последующие результаты не меняют уже формируемый файл. Порядок соответствует текущей сортировке с устойчивым порядком для равных значений.
- `Invalid` можно экспортировать только как исходные строки или отчёт. При пустой области действие недоступно с понятной причиной. Нельзя сообщать об успехе при частичном или неуспешном сохранении.

## 9. Данные, приватность и архитектура

### FR-12. Данные и хранение

По умолчанию сохраняются записи, исходные строки, реквизиты, метаданные импорта, последние результаты со снимком использованного профиля, все параметры проверки и тема. Рабочая сессия автоматически восстанавливается при запуске. `Queued`/`Checking` восстанавливаются как `Cancelled`; сетевые проверки не запускаются сами.

Каталог выбирается стандартным `app_data_dir`: Linux — `$XDG_DATA_HOME/dev.hightemp.proxypulse` либо `~/.local/share/dev.hightemp.proxypulse`, macOS — `~/Library/Application Support/dev.hightemp.proxypulse`, Windows — `%APPDATA%/dev.hightemp.proxypulse`. Стабильный старый identifier сохраняется при переименовании в ProxyVouch, чтобы обновление не потеряло локальную рабочую сессию. Путь виден в `Backup & restore`. На Unix права каталога 0700, файлов 0600. Файлы содержат пароли и пользовательские URL без шифрования; это явно написано в интерфейсе.

Фоновый поток сохраняет изменения примерно раз в секунду атомарной заменой файла; настройки и подтверждённый импорт архива записываются до сообщения об успехе. Сохраняется предыдущая корректная копия, повреждённый основной файл при восстановлении не уничтожается. Если ни одна копия не читается, автоматическая перезапись блокируется с ошибкой. Второй экземпляр не может записать поверх данных первого. Ошибка сохранения архива при импорте не изменяет текущие настройки и список. Старые настройки темы/лимитов переносятся при первом запуске без изменения исходного файла.

`Backup & restore` экспортирует версионированный JSON: вся сессия, прокси с результатами или только настройки. Предпросмотр импорта показывает состав файла без передачи реквизитов в UI. Для списка доступны `Merge` (точные дубликаты пропускаются, существующие результаты сохраняются), `Replace` (в том числе сохраняются дубликаты из архива) и пропуск; настройки применяются отдельным выбором. Пустой архив списка позволяет явно очистить список. Формат, версия, поля и лимит 100 000 строк проверяются до изменения состояния; размер архива ограничен 256 MiB. Неизвестные версии и CSV/JSON-отчёты не принимаются как резервные копии. Во время проверки импорт архива запрещён.

Секреты маскируются в таблице, предпросмотре и деталях; просмотр — явным действием. Логи, ошибки, события прогресса и аварийные отчёты не содержат пароль, исходную строку с реквизитами или полный чувствительный URL. Полные реквизиты передаются в UI только по явной операции просмотра/экспорта; сама запись хранится в Rust-ядре. Внешняя телеметрия отсутствует.

`Clear list` очищает текущий и автоматически сохранённый список; предыдущая резервная копия может ещё содержать удалённые строки. Это не операция гарантированного уничтожения секретов. Приложение не обещает защиты от дампов процесса или системного swap. Буфер обмена и экспортный файл содержат именно выбранные пользователем данные; приложение не подменяет их масками и не очищает чужое содержимое буфера таймером.

### 9.1. Предлагаемая структура

- Tauri 2: десктопная оболочка, системные диалоги, clipboard и ограниченный IPC.
- React + TypeScript + Vite: английский интерфейс, виртуализированная таблица; это исходный выбор для нового проекта, не требование к сетевому ядру.
- Rust: `parser`, `model`, `checker`, `scheduler`, `export`, `storage`. Сетевые операции выполняются вне UI-потока.
- Сетевой клиент выбирается после T-002: проверить libcurl bindings и Rust-клиенты по реальным HTTPS proxy / SOCKS4a / SOCKS5h / отмене / TLS-возможностям. Наличие `socks` feature само по себе не доказывает всю матрицу. Системный `curl` как обязательная внешняя программа не используется.
- Типизированные команды и ошибки, `Result` для ожидаемых отказов, без `panic` на пользовательских данных. Ответы UI содержат стабильный код и английское сообщение.
- У каждой операции есть `run_id`, у строки — стабильный `proxy_id`, у результата — версия записи и снимок профиля. События агрегируются, поздние результаты отбрасываются по идентификаторам.
- Tauri capabilities ограничиваются необходимыми действиями локального окна; импорт/экспорт проходят через Rust и выбранные пользователем пути. Удалённые страницы в привилегированном webview не загружаются; данные отображаются как текст. Модель разрешений основана на [Tauri Capabilities](https://v2.tauri.app/security/capabilities/).

### 9.2. Минимальная модель

| Сущность | Обязательные данные |
| --- | --- |
| `ImportIssue` | ID, источник/номер строки, исходная запись, код/поле ошибки; нормализованный адрес может отсутствовать. Доступен как `Invalid`, в сетевую очередь не попадает |
| `ProxyEntry` | ID, версия, источник/номер строки, исходная запись, нормализованный host/port, requested protocol, DNS mode, optional credentials, label |
| `CheckProfile` | ID, тип валидатора, основной/резервный URL, ожидаемый статус/тело, лимиты |
| `CheckRun` | ID, снимок настроек/профиля, выбранные proxy ID, начало/конец, прогресс, отмена |
| `CheckAttempt` | Кандидат/режим DNS, адрес проверки, стадия, времена, подтверждённый протокол, код и безопасное сообщение ошибки |
| `CheckResult` | Proxy ID/version, run ID, статус, requested/detected protocol, authentication, снимок профиля, IP, измерения, checked_at, попытки |

## 10. Нефункциональные требования

| ID | Требование | Проверка |
| --- | --- | --- |
| NFR-01 | Импорт 10 000 корректных строк до 2 с; 100 000 до 10 с | Release-сборка, локальный синтетический файл, описанная эталонная машина |
| NFR-02 | При 100 000 строках ввод/фильтры реагируют до 200 мс p95; обновления прогресса не чаще 10 раз/с | Измерение GUI; виртуализация и пакетные события |
| NFR-03 | `Stop` отражается в UI до 200 мс; сетевые задачи освобождаются до 1 с | Управляемые зависающие серверы, проверка сокетов и задач |
| NFR-04 | Параллельность, частота и сроки не превышают настройки | Инструментированные сетевые фикстуры и часы |
| NFR-05 | Память приложения при 100 000 коротких строках и concurrency=20 до 500 MiB суммарного RSS процессов | Release-сборка, фиксированный набор данных; измерение отдельно по ОС |
| NFR-06 | Реквизиты не попадают в логи/ошибки; clipboard/файлы соответствуют выбранной области | Синтетические уникальные секреты и проверка артефактов |
| NFR-07 | GUI работает на каждой заявленной ОС | Нативный smoke: импорт → реальный локальный прокси → проверка → clipboard → файл |
| NFR-08 | Проверки воспроизводимы без публичных прокси | Локальные серверы для всех протоколов, авторизации и негативных сценариев |

Числа NFR — целевые критерии, не результаты текущего измерения. Эталон: машина с 4 логическими CPU и 8 GiB RAM; точные CPU/ОС/архитектура и размеры строк фиксируются в отчёте. Время массовой сетевой проверки зависит от лимитов и серверов и не входит в норматив времени импорта.

## 11. Сквозные критерии приёмки

| ID | Критерий |
| --- | --- |
| AC-01 | F-07 разбирается в host, port, username, password и SOCKS5 без потери полей; реквизиты в UI скрыты |
| AC-02 | Поддерживаются все F-01–F-22 по описанным условиям; неоднозначные записи требуют шаблона, ошибочные показывают номер и причину |
| AC-03 | Список без протокола успешно проверяется через локальные HTTP, HTTPS, SOCKS4, SOCKS4a и SOCKS5-серверы; открытый непрокси TCP-порт не даёт `Working` |
| AC-04 | Явный неправильный протокол не заменяется автоматически; `Detect again` позволяет выполнить отдельную проверку Auto |
| AC-05 | Неверный/отсутствующий пароль, неподдерживаемый метод и SOCKS4 USERID обрабатываются различимо; пароль не отбрасывается |
| AC-06 | Сертификаты прокси и назначения проверяются независимо; ошибка одного из слоёв не даёт успешный результат |
| AC-07 | SOCKS5 local/remote DNS различаются в проверке и экспорте; IPv6 и percent-encoding выдерживают parse → export → parse |
| AC-08 | HTTP 407 прокси, отказ CONNECT, HTTP 403/429/5xx назначения и сбой локальной сети классифицируются по FR-08; массовый сбой endpoint не загрязняет `Failed` |
| AC-09 | Отмена сохраняет готовые строки, завершает задачи, корректно отмечает остальные; поздний ответ старого запуска не меняет новый |
| AC-10 | `Copy/Save working` и `Copy/Save failed` содержат строго свои группы; `Checked` включает `Inconclusive`, но не отменённые и невалидные |
| AC-11 | TXT/CSV/JSON, реквизиты, спецсимволы, неизвестный протокол, пустая выборка и ошибка записи обрабатываются без молчаливой потери данных |
| AC-12 | `HTTP_PROXY`, `ALL_PROXY`, `NO_PROXY` и системные настройки не обходят выбранный прокси; прямое соединение к endpoint отсутствует |
| AC-13 | Дубликаты с разными реквизитами/режимами остаются разными; редактирование сбрасывает результат; профиль результата не меняется задним числом |
| AC-14 | Достигнуты и измерены NFR-01–NFR-06; результаты опубликованы в английском отчёте проекта |
| AC-15 | На каждой заявленной ОС пройден NFR-07; отсутствие проверки явно сохраняется как незавершённая работа |
| AC-16 | Все продуктовые строки, README и код на английском; PRD.md/TASKS.md на русском |
| AC-17 | После перезапуска восстановлены список, реквизиты, настройки и последние результаты; незавершённые проверки отменены; ошибки хранения видимы |
| AC-18 | Архивы всей сессии/прокси/настроек проходят export → import; merge/replace и сбои валидации/записи не приводят к незаявленной потере данных |

## 12. Риски и решения до реализации

| Вопрос | Принятое направление | Условие закрытия |
| --- | --- | --- |
| Полная поддержка протоколов выбранной библиотекой | Обязательный технический spike, без молчаливого урезания MVP | T-002: локальная матрица и решение о зависимости |
| Недоступность публичного IP echo | Настраиваемый профиль, резервный адрес и `Inconclusive` | T-003: контракт валидатора, воспроизводимые тесты отказов |
| Различия TLS, DNS и отмены по ОС | Нативные проверки, фиксированные версии зависимостей | T-001 и этап выпуска |
| Неоднозначные форматы поставщиков | Детерминированный парсер и предпросмотр | Полный корпус F-01–F-22 и отрицательных примеров |
| Нагрузка от автоперебора | Последовательные кандидаты, очередь, общий deadline и rate limit | Измеренные пределы без умножения concurrency на число протоколов |
| Ошибка, принятая за нерабочий прокси | Отдельные стадии, профиль результата и `Inconclusive` | Негативные сценарии AC-08 |

Изменение обязательного требования оформляется одновременно в PRD.md и TASKS.md. Незавершённый spike не считается реализованной возможностью.
